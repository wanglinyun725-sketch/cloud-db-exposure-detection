# CloudDB-PathBench 评测基准详解

**所属工作点**：研究内容一 —— 面向云数据库高敏数据暴露路径侦测的评测基准构建
**一句话定位**：把"云数据库暴露路径侦测"这一模糊的安全运营问题,**形式化为一个可生成、可标注、可评判、可复现**的标准任务,并配套受控数据与评测协议。基准的贡献在于**任务形式化、合法性约束、可控生成与严格切分**这一整套方法论,而非某个打分函数。

---

## 一、动机:为什么必须自己造基准

现有安全评测资源无法直接支撑本任务:

| 现有基准 | 关注点 | 为何不适用 |
|---|---|---|
| CIC-IDS 等入侵检测 | 网络流量层单点入侵 | 不面向"通往具体高敏字段的路径" |
| HackTheBox / CTF | 红队渗透对抗 | 无标准答案、不可量化复现 |
| SecBench 等 | LLM 通用安全问答 | 非路径级、无证据链标注 |

**核心缺口**：缺少面向"**权限链 × 数据流 × 敏感级**"三轴交叉暴露路径的、**可控且可复现**的评测基准。CloudDB-PathBench 为填补此缺口而建。

---

## 二、贡献之一:任务的严格形式化(把模糊问题变成可评测任务)

这是基准最核心的贡献——**将"找暴露路径"定义成一个输入、输出、评判都明确的计算任务**。

**基本单元(调查案例)**：
$$\text{Case}=(\sigma_0,\;G,\;\mathcal{A}_{tool},\;y^{*})$$

- $\sigma_0$：初始信号(告警/异常/公网暴露标记),仅携带**局部**信息,是调查起点;
- $G$：世界快照(完整风险图),**不直接给出**,须由方法通过工具逐步获取;
- $\mathcal{A}_{tool}$：可用工具集;
- $y^{*}=(p^{*},\,e^{*},\,\tau^{*})$：gold 标注(标准路径、标准证据、标准调查轨迹),**对被测方法全程不可见**,仅供评判。

**任务映射与评判协议**：
$$\underbrace{(\sigma_0,\,G)}_{\text{输入}}\;\xrightarrow{\;\text{被测方法}\;}\;\underbrace{\hat{Y}=(\hat p,\hat e,\text{PathType})}_{\text{输出}}\;\xrightarrow{\;\text{对照}\;}\;\text{Score}(\hat{Y},\,y^{*})$$

**关键设计——信息不对称**:方法开始时只有 $\sigma_0$,必须主动调查还原真实路径;$y^{*}$ 不进入其上下文。这使评测**同时考察判定正确性与主动调查能力**,而非静态问答。

> 价值:此前"暴露路径侦测"没有统一的输入输出与评判口径,不同工作无从比较;本形式化提供了统一口径。

---

## 三、贡献之二:用形式语言定义"什么是合法暴露路径"

暴露路径不是任意节点串,而须满足**类型约束 + 文法约束**双重形式化定义。

**局部类型约束**：对任意相邻三元组 $(v_i,e_i,v_{i+1})$,须满足边类型 $\tau_E(e_i)$ 的源—目标类型规则(由类型转移矩阵给定)。

**全局文法约束**：合法路径的边类型序列
$$\sigma(P)=\big(\tau_E(e_1),\,\tau_E(e_2),\,\ldots,\,\tau_E(e_{k-1})\big)\in\mathcal{R}$$
其中 $\mathcal{R}$ 为一个**正则语言**,刻画"网络可达 → 身份可访问 → 数据高敏"的三段式攻击语义(须依次包含至少一条 `can_connect`、一条 `has_permission`、一条 `contains`/`classified_as`)。

**入口集 / 目标集(路径两端的形式化)**：
$$Entry(G)=\{v\mid \tau_V(v)\in\{Network,Identity\}\land is\_external(v)\}$$
$$Target(G)=\{v\mid \tau_V(v)\in\{DBObject,SensitiveTag\}\land is\_high\_value(v)\}$$

> 价值:用**正则文法**规定合法路径的形态,是比"经验规则"更严格的形式化——它使"路径是否合法"成为**可判定**的问题,也是约束搜索完备性的基础。

## 四、贡献之三:可控、可复现的参数化生成机制

基准数据由一个**参数化生成映射**产出,而非人工逐条编写:
$$\mathcal{G}:\;\big(\text{scenario},\;\theta_{len},\;\theta_{comp},\;\theta_{obf},\;\text{seed}\big)\;\longmapsto\;\text{Case}$$

- $\theta_{len}$：路径长度;$\theta_{comp}$：组合复杂度(串联弱点数);$\theta_{obf}$：混淆因子(干扰节点/噪声量);
- **可控**:三类参数如旋钮可调,生成**难度分级**的题目;
- **可复现**:$\mathcal{G}$ 为确定性映射,**同参数 + 同 seed ⟹ 同数据**,保证不同方法在完全一致的题目上公平对比。

**四层构建管线**:
1. 场景来源映射:真实事故模式 → S1–S6 场景模板;
2. Schema 池构建:按行业(金融/医疗/电商)构建真实感库表 Schema 池,生成时采样;
3. 五阶段参数化合成:场景实例化 → 节点生成 → 边合成 → 敏感性注入 → 审计/行为合成;
4. 确定性校验:14 条 SHACL 式结构约束逐样本校验。

**双来源互补**:除合成数据外,另以开源靶场 **CloudGoat** 的真实 Terraform 配置为种子,解析映射为风险图,贴近真实环境。

> 价值:"可控生成"使基准能按难度梯度评测方法(scaling),"可复现"使结果可被他人复算——这正是 GSM-Symbolic 等参数化基准被认可的核心。

## 五、贡献之四:六类实战场景模板(覆盖典型路径与拒答边界)

| 编号 | 场景 | 风险模式 |
|---|---|---|
| S1 | 公网暴露 + 高敏数据未保护 | 入口直接暴露,直达高敏数据 |
| S2 | 低权限账号权限过宽 | 权限过宽导致越权触达 |
| S3 | 异常 IP / 夜间访问 + 批量查询 | 行为异常驱动的可疑访问 |
| S4 | 外部主体 + 白名单过宽 | 跨账号/外部实体经宽松白名单进入 |
| S5 | 未开启审计 / 保护 + 高敏资产 | 治理缺失下的高敏暴露 |
| S6 | 证据冲突(权限有但网络不通等) | 专门考察"证据不足即拒答"的边界 |

每类支持生成**正例(真实暴露)与负例/证据冲突**,使基准既含"应判有风险",也含"应正确拒答"的样本。S6 尤其用于检验方法在证据矛盾时是否会误报。

## 六、贡献之五:四种正交切分(评测严格性的形式化保证)

| 切分 | 考察能力 | 形式化约束 |
|---|---|---|
| Random | 同分布基本性能 | 随机划分 |
| **Unseen Schema** | 对未见库表结构的泛化 | $\{\sigma(i):i\in\mathcal{X}_{tr}\}\cap\{\sigma(i):i\in\mathcal{X}_{te}^{schema}\}=\varnothing$ |
| **Unseen Risk Combo** | 对未见风险组合的泛化 | 组合签名 $\rho(x)=\mathrm{sort}(L(x))$ 训练/测试不重合 |
| **Evidence Corruption** | 证据扰动下的鲁棒性 | 对证据人为损坏,检验能否正确判"证据不足" |

其中 schema 指纹 $\sigma(i)=\mathrm{hash}(\{(name,type,sens\_level)\}_{f})$。**"集合不相交"这一约束是关键**——它从形式上保证测试集"真的没被见过",使 OOD 泛化评测严格、不掺水。

---

## 七、标准答案与评测指标

**Gold 标注三元组** $y^{*}=(p^{*},e^{*},\tau^{*})$:标准路径、标准证据集、标准调查轨迹。$\tau^{*}$ 记录从 $\sigma_0$ 还原路径的最优动作序列,用于**轨迹级**评测。

**指标体系(设计 21 项,四维)**:
- 路径准确性:Path Recall、Node-F1、Edge-F1、Path-EM;
- 证据完整性:Evidence Precision、Evidence Coverage、Hallucination Rate;
- 排序质量:NDCG@k、MAP;
- 鲁棒性/调查效率:各 OOD 切分表现、EIC Pass Rate,轨迹级 EQP、CS、pass@k。

## 九、质量验证与当前边界

**质量验证**:14 条 SHACL 约束全样本校验(节点/边类型合法、路径合法性、敏感度一致性、expected_type 合法等),结构无误;6 场景均衡覆盖、3 行业分布合理;参数化生成支持难度梯度。

**已完成**:任务形式化、合法性文法、入口/目标定义、参数化生成映射、四层管线、六类场景模板、真实靶场接入、14 条 SHACL 校验、四种正交切分、指标体系、60 + 20 数据集。

**进行中 / 下一步**:规模化扩充与更细难度梯度;标注一致性 $\kappa$ 的系统评估;在基准上完成多基线系统性对比与统计分析。
