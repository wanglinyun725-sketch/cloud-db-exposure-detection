## 二、算法层面的核心工作(重点)

### ① 统一风险图 CDB-RG 形式化建模

**任务输入形式化**（六元组环境快照）：
$$S=(\mathcal{A},\mathcal{N},\mathcal{I},\mathcal{D},\mathcal{L},\mathcal{C})$$
分别为账号、网络、IAM 策略、数据库对象、敏感标签、审计日志。

**统一风险图定义**：
$$G=(V,\;E,\;\tau_V,\;\tau_E,\;\varphi_V,\;\varphi_E)$$
其中 $V$ 为节点集,$E\subseteq V\times V$ 为有向边集,$\tau_V:V\to T_V$ 为节点类型函数,$\tau_E:E\to T_E$ 为边类型函数,$\varphi_V,\varphi_E$ 为节点/边属性函数。

**入口集与目标集**：
$$Entry(G)=\{v\mid \tau_V(v)\in\{Network,Identity\}\land is\_external(v)\}$$
$$Target(G)=\{v\mid \tau_V(v)\in\{DBObject,SensitiveTag\}\land is\_high\_value(v)\}$$

**类型体系**：设计 8 类节点、10 类边的完整类型体系(Identity / Network / DBInstance / DBObject / SensitiveTag / Control / AuditEvent / RiskFinding 等;边含 can_assume / can_connect / has_permission / contains / classified_as 等)。

**支撑证据**：
- 代码：`src/graph/graph_builder.py`,`build_graph()` 以 NetworkX MultiDiGraph 构建类型化有向图。
- 实测：单个 CloudGoat 样本实建 **20 节点 / 29 边**,节点覆盖 Identity/DBInstance/DBObject/Network/SensitiveTag,边覆盖 can_assume/can_connect/has_permission/contains/classified_as。
- 说明：类型体系定义 8 类节点、10 类边,具体场景按需实例化其中子集(当前样本用到 5 类节点、5 类边)。

### ② 正则文法约束的暴露路径枚举算法

**问题**：在风险图上枚举从入口到高敏目标的**合法**暴露路径,避免组合爆炸。

**路径合法性(局部约束)**：对任意相邻三元组 $(v_i,e_i,v_{i+1})$,须满足 $\tau_E(e_i)$ 的源—目标类型约束。

**边类型序列的文法约束(全局约束)**：合法路径的边类型序列
$$\sigma(P)=(\tau_E(e_1),\ldots,\tau_E(e_{k-1}))\in\mathcal{R}$$
其中 $\mathcal{R}$ 为刻画"网络可达 → 身份可访问 → 数据高敏"三段式语义的正则语言(须依次含至少一条 `can_connect`、一条 `has_permission`、一条 `contains`/`classified_as`)。

**算法特征**：在类型转移矩阵约束下的路径枚举 + 长度上界 + 三层剪枝,将搜索空间约束到语义合法子空间;具备**枚举完备性**(不遗漏满足约束的真实路径)。

**支撑证据**：
- 代码：`src/graph/constrained_search.py`,`constrained_dfs()` + 类型转移约束 `VALID_EDGE_TRANSITIONS` + `REQUIRED_EDGE_TYPES`。
- 论文：第 3.2 节路径合法性与正则文法约束;第 4.2 节约束搜索算法与完备性分析。

> **命名要点**：本算法不是朴素图遍历,而是**正则文法约束下的合法暴露路径枚举**,核心在"约束"与"完备性",而非遍历本身。

### ③ 字段—表—实例敏感性层次聚合算法(含单调性证明)

**问题**：敏感度如何沿"字段→表→实例"逐层传递与汇聚,支撑高价值目标判定。

**表层聚合**：
$$S_{table}(t)=\max_{f\in Fields(t)}S_{field}(f)+\lambda_1\cdot|HighSens(t)|+\lambda_2\cdot\frac{|Sens(t)|}{|Fields(t)|}$$

**实例层聚合**：
$$S_{instance}(i)=\max_{t\in Tables(i)}S_{table}(t)+\mu_1\cdot|HighTables(i)|+\mu_2\cdot|ExposedTables(i)|$$

**定理(单调性)**：若某字段敏感度上升 $\tilde S_{field}\ge S_{field}$,则聚合后 $\tilde S_{table}\ge S_{table}$ 且 $\tilde S_{instance}\ge S_{instance}$。
**证明思路**：$\max$ 保序 + 计数项 $|HighSens|,|Sens|$ 单调不减 + 权重 $\lambda,\mu\ge0$,三项相加仍单调不减(逐层归纳)。

**意义**：保证"底层字段越敏感 → 上层目标价值越高"这一直觉在数学上成立,为高价值目标判定与风险排序提供理论依据。

**支撑证据**：
- 论文：第 3.3 节三层聚合模型;第 3.3.3 节单调性完整证明(表层 + 实例层归纳)。
- 代码：`src/graph/gate_score.py` 中 target/sense 维度沿 `contains`/`classified_as` 计算敏感度聚合。

### ④ 证据完整性约束判定演算 EIC(核心贡献)

**核心思想**：表达—判定分离——大模型仅产出五维结构化证据,**风险判定完全由确定性算子完成**。

**五维证据向量**：
$$\vec{\varepsilon}(P)=(\varepsilon_{entry},\;\varepsilon_{reach},\;\varepsilon_{perm},\;\varepsilon_{target},\;\varepsilon_{sense})$$
分别刻画入口暴露、网络可达、权限可获、目标敏感、行为可观测,取值 $\in[0,1]$。

**判定算子**：
$$\mathrm{EIC}(P)=\mathrm{Gate}(P)\cdot\mathrm{Score}(P)$$

**硬门(一票否决)**：
$$\mathrm{Gate}(P)=\prod_{d\in\{entry,reach,perm\}}\mathbb{1}\!\left[\varepsilon_d(P)\ge\tau_d\right]$$

**风险评分(加权聚合)**：
$$\mathrm{Score}(P)=\prod_{d}\varepsilon_d(P)^{w_d},\quad \textstyle\sum_d w_d=1$$

**风险量化排序(对数几率)**：
$$\mathrm{Risk}(P)=\sigma\!\left(\sum_d \beta_d\log\frac{\varepsilon_d}{1-\varepsilon_d}+\beta_0\right)$$

**四条性质定理**：
1. **单调性**：$G'\supseteq G \Rightarrow \mathrm{EIC}(P;G')\ge \mathrm{EIC}(P;G)$——证据越多判定越稳,补证据不会使风险凭空消失。
2. **零元素性质**：某硬维度 $\varepsilon_d<\tau_d \Rightarrow \mathrm{EIC}(P)=0$——关键证据缺失必判"证据不足",不瞎报(抗幻觉的数学保证)。
3. **假设空间收缩性**：每次 Gate 关闭使候选假设空间严格收缩,保证收敛。
4. **多项式可判定性**：$\mathrm{EIC}(P)$ 可在 $O(|P|\cdot\max(|V|,|E|))$ 内判定,不会挂起。

**意义**：把判定从 LLM 黑箱中彻底剥离,使判定**可追溯(每个 Gate 对应具体证据)、可复现(纯确定性)、抗幻觉(无据即否决)、可审计**。

**支撑证据**：
- 论文：第 4.3 节 Gate–Score 验证演算及四条性质证明;第 4.4 节对数几率风险模型。
- 代码：`src/graph/gate_score.py`,`gate_score()` 实现 Gate 一票否决 + Score 加权;`compute_evidence_vector()` 确定性计算五维;LLM 不参与数值与判定(`agent_graph.py` stage4 注释明确"不覆盖数值")。

### ⑤ 硬证据一票否决的自适应提前终止(含等价性)

**问题**：在证据获取阶段避免对注定失败的路径浪费工具与模型调用。

**逐维代价优先探查**：按 $entry\to reach\to perm$（代价低、最可能否决优先）逐维计算 $\varepsilon_d$。

**剪枝准则**：
$$\mathrm{Gate}(P)=0 \;\land\; \widetilde{IG}(P)<\delta_{IG}\;\Rightarrow\;\texttt{prune}(P)$$
即某硬维度不达标、且补强的信息增益低于阈值时,当场判"证据不足"并终止后续取证。

**判定等价性**：由 ④ 的零元素性质,提前终止**不改变任何最终判定结果**——被提前剪掉的路径,即使走完整流程也必被判 $\mathrm{EIC}=0$。故该机制是"无损加速"。

**支撑证据**：
- 代码：`src/agent/agent_graph.py`,`gate_precheck()` + `compute_one_dimension()` 实现逐维查验与提前终止。
- 实测(见第五节)：68 条候选路径中 17 条被提前终止,证据损坏切分 100% 正确拒答,判定结果不变。

### ⑥ 信念状态驱动的自主探索形式化框架

**信念状态**：
$$\mathcal{S}_t=(\mathcal{H}_t,\;\mathcal{E}_t,\;\mathcal{B}_t)$$
分别为活跃假设集(候选路径)、证据库(已获观测)、信念(对每个假设的当前 EIC 评估)。

**动作空间**：
$$\mathcal{A}=\{\texttt{query},\;\texttt{prune},\;\texttt{expand},\;\texttt{confirm},\;\texttt{terminate}\}$$
将暴露路径侦测建模为**在确定性约束下逐步逼近的序贯决策过程**。

**当前落地**：智能体在两个决策点自主决策——(a) 候选路径的**风险优先级排序**(先查哪条);(b) 每条路径的**按需工具调度**(调哪几个工具)。判定权始终归确定性算子。

**支撑证据**：
- 论文：第 4.1 节假设驱动 Agent 循环的形式化(信念状态 + 动作空间 + 转移规则)。
- 代码：`agent_graph.py` stage2(LLM 路径排序)、stage3(LLM function-calling 工具调度)。

> **诚实边界**：完整的信念状态闭环(信息增益驱动的动态 `query`/`expand`)已给出形式化定义,其在线迭代实现列为下一阶段工作(见第六节)。
