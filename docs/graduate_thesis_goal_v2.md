# Cloud DB PathBench 研究生毕业设计 Goal v2

版本日期：2026-07-29  
目标性质：研究与工程双重验收契约  
当前基线：v8 数据与实验结果，项目客观评估约 74/100

## 1. 总目标

将 Cloud DB PathBench 建设为一个可复现、可审计、结论不过度外推的研究型毕业设计：

1. 基于真实、公开、可追溯且非 AI/脚本臆造的云安全证据，建设跨云攻击与暴露路径基准；
2. 实现以 ReAct、Tool Use 和确定性验证工具为核心的渐进式路径发现方法，在有限查询预算下提升路径发现效率、证据完整性和安全判定可靠性；
3. 形成 2 个已经被充分实验支持的独立创新点，并以第 3 个创新点作为达标后晋升项；
4. 用冻结协议、人工金标准、独立样本单位、置信区间、效应量和多重比较校正支持结论；
5. 交付可一键复现的代码、数据清单、实验结果、论文、答辩材料和局限性说明。

“优秀”是项目追求的证据标准，不承诺学校最终评分；最终评价以论文质量、实验结果和学院评审为准。

## 2. 核心研究问题

- RQ1：在相同工具调用预算下，EC-ReAct 是否比 vanilla ReAct、固定顺序查询和随机查询更准确或更节省查询成本？
- RQ2：作用域感知的供应商事实工具和 Unknown/不可判定状态，是否能降低缺证据条件下的错误 Reachable 判定？
- RQ3：CP-Cert 证据证书是否能提升路径级精确率、证据覆盖率和结果可审计性？
- RQ4：上述结果能否在来源隔离、谱系隔离的 AWS、Azure、GCP 数据上保持，而不是依赖近重复样本或单一供应商？

## 3. 创新点及独立验收

### C1：真实跨云证据路径基准

贡献：提出面向云数据库/云数据资源暴露路径的来源可追溯数据协议，将配置事实、供应商运行结果、否定证据和 Unknown 控制统一为路径级标注对象。

必须同时满足：

- 原始事件、配置和供应商结果均可回溯至公开 URL、DOI、仓库提交或官方制品；
- 保存来源、许可证、版本/提交、文件哈希和精确定位信息；
- 不用 LLM 或自写脚本生成“真实事件”；脚本仅可解析、规范化和验证公开原始材料；
- 训练、开发、测试按来源和攻击谱系隔离；
- 完成双人独立标注、分歧仲裁和一致性报告。

### C2：预算约束的作用域感知 EC-ReAct

贡献：把路径发现建模为带成本的序贯决策过程，由 Agent 根据当前证据状态选择下一探查工具，在有限预算下渐进补齐关键边。

形式化：

- 状态：当前证据图、四值事实记忆、已用预算、未决关键边；
- 动作：调用一种具有明确输入/输出/适用范围的探查或验证工具；
- 代价：工具调用数、时延或标准化成本；
- 目标：在错误 Reachable 风险受控的条件下，最大化路径正确性与证据覆盖率；
- 停止条件：证书已充分、预算耗尽或剩余动作期望信息增益不足。

必须由完整方法与下列消融对比支撑：

- 去掉 Pareto/主动动作选择；
- 去掉 provider scope gate；
- 去掉四值记忆；
- 去掉预算停止规则；
- 与 vanilla ReAct、固定顺序、随机顺序和 full-query 上界比较。

### C3：CP-Cert 可验证路径证书（晋升项）

贡献：将 LLM 的路径候选交给确定性验证器，输出“成立、否定、冲突、未知”四值证书，明确每条边的证据来源、工具结果和失败原因。

只有在冻结的人类金标准测试集上同时提升路径级指标和可审计性时，才作为独立创新点写入摘要；否则降级为 C2 的安全机制，不夸大为第三个创新。

LangGraph 仅作为可复现编排实现，不单独声称为创新。

## 4. 数据集硬门槛

冻结主实验前至少满足：

- 不少于 40 个独立攻击/配置谱系；
- AWS、Azure、GCP 均有覆盖，其中任一云平台不超过总谱系的 60%；
- 不少于 6 个相互独立的上游发布者或数据源；
- 任一单一上游来源不超过总谱系的 40%；
- 同时包含 Reachable、Not-Reachable 和 Unknown/证据不足控制；
- 近重复检测按来源、模板、资源拓扑和事件序列进行，而非只比较文本；
- 至少 30 个独立谱系进入双人盲标测试子集，或在总量允许时全量双标；
- 报告 Cohen's kappa 或 Krippendorff's alpha，目标不低于 0.70；低于目标也必须如实报告、分析分歧并仲裁，不得删除难例抬高一致性；
- 人工金标准必须由真实人员完成，LLM 预标注不得冒充 human gold。

## 5. 冻结实验设计

### 5.1 冻结内容

主实验前冻结并记录：

- 数据清单、谱系 ID、来源 ID 和数据哈希；
- train/dev/test 划分及随机种子；
- 主指标、次指标、统计检验和成功阈值；
- 方法与基线配置、工具契约、提示词版本；
- 代码提交哈希、依赖锁、模型名称/量化/服务版本；
- 完整运行计划和失败保留规则。

测试集冻结后不得用于调参。任何事后新增分析必须标注为 exploratory。

### 5.2 模型与基线

- 至少两个模型能力层级：本地 Qwen2.5-7B 作为资源可复现基线，另加一个更强且版本固定的模型；
- 相同模型、相同工具集、相同预算下比较方法；
- 基线至少包含 vanilla ReAct、固定顺序、随机顺序、full-query；
- 区分“模型能力提升”和“方法贡献”，不得只用更强模型证明新方法有效。

### 5.3 主要指标

- 状态级：macro-F1、balanced accuracy、Unknown/abstention 质量；
- 安全性：错误 Reachable 数与比例、unsupported-path rate；
- 路径级：exact node/edge precision、recall、F1，完整路径命中率；
- 证据级：关键边证据覆盖率、证书完整率、冲突发现率；
- 效率级：工具调用数、标准化成本、时延及 accuracy-cost Pareto 前沿。

### 5.4 统计规范

- 独立攻击/配置谱系是主要统计单位，重复运行只估计稳定性，不扩大样本量；
- 主比较使用配对精确检验、置换检验或分层 bootstrap；
- 报告 95% 置信区间与效应量，不只报告 p 值；
- 多重比较采用 Holm 校正；
- 主实验前完成功效分析，并据此调整谱系数量；
- 保存全部种子、失败、超时和无效输出，禁止只挑最好结果。

### 5.5 最低成功判据

完整方法至少满足以下条件，才可声称“方法有效”：

- 相比主要基线，预注册主指标达到统计显著，或达到预注册的实际等效改进阈值；
- 在准确率不劣于基线的前提下，查询成本降低至少 20%，或路径级 F1 提升至少 10 个百分点；
- 不增加错误 Reachable；若样本量不足以证明零风险，则报告其置信区间上界；
- 人工金标准上的 exact edge F1 不低于 0.60，并显著或实质性优于 vanilla ReAct；
- 至少两个跨来源/跨平台 held-out 切片复现实质性收益。

若未过线，应把结论改写为负结果或边界条件，不得更换指标包装成成功。

## 6. 论文与复现交付物

- 可一键执行的数据审计、基线、主实验和统计分析命令；
- README、环境锁、数据许可证清单、来源 manifest、模型与运行 manifest；
- 单元测试、协议验证测试和结果一致性检查；
- 论文完整章节：问题定义、相关工作、方法、数据、实验、威胁与局限、伦理与复现；
- 关键公式均定义变量、假设和优化目标，并与代码实现一一对应；
- 4–6 张可发表质量的核心图表；
- 中期说法—最终证据对照表，主动修正不再成立的旧表述；
- 答辩 PPT、演示脚本和质疑清单；
- 至少完成方法、统计和云安全语义三轮“审稿人式”压力测试。

科研技能用于文献检索、实验设计、功效分析、统计审计、图表和同行评审；任何技能输出都必须回到原始论文、代码和真实数据核验，不能替代证据。

## 7. 完成定义

仅当以下项目全部有可检查的仓库证据时，本 Goal 才能标记完成：

1. 数据硬门槛通过，且 human gold 不再为 0；
2. 冻结主实验按预注册协议完整执行；
3. C1、C2 均有代码、消融和统计结果支持；
4. C3 通过独立验收，或被诚实降级且论文只主张两个创新点；
5. 主张与数据一致，路径级指标不再缺失或为 0；
6. 复现包在干净环境通过；
7. 论文、图表、答辩材料和局限性说明齐全；
8. 代码与必要文档已推送到 GitHub，最终审计无阻断项。

当前 263 项测试通过、v8 数据和已有实验是可靠的阶段性基础，但不等同于本 Goal 完成。

## 8. 当前优先级

1. 先做功效分析和谱系扩充计划，锁定需要新增的真实数据规模；
2. 同步启动双人标注材料与第二标注人流程，解决 human gold=0；
3. 修复路径抽取与证书对齐，使 exact edge F1 从 0 达到可评估水平；
4. 冻结协议后再运行更强模型与主实验；
5. 最后写论文结论，避免先写结论再寻找支持结果。
