# 论文重构与三项创新点提炼

> 整理来源：`新建 文本文档.txt`，并结合《面向云数据库高敏数据暴露路径侦测的相关研究深度调研报告.pdf》的研究脉络。
>
> 目标：把原先“Demo + Benchmark + Agent/GateScore”的松散结构，重构为一条有明确工作量、方法设计和实验支撑的硕士论文主线。

---

## 1. 中期被批评的核心问题

原方案最容易被批评的点不是“完全没有东西”，而是**工作被组织错了**。

当前 Demo 中大量逻辑都围绕“路径是否网络可达、权限是否满足、目标是否敏感”做多轮过滤：

- 函数层过滤：约束 DFS / 类型约束 / 必要边过滤；
- AI 层过滤：LLM 排序、解释、补证；
- GateScore 层过滤：entry / reach / perm / target / sense 再判一次；
- 实验层仍然在证明类似的“路径过滤有效”。

这导致老师会感觉：

> 你只是围绕同一个网络可达性/权限可达性问题，换了几种包装反复校验，没有形成三块独立的研究工作量。

因此，后续不应该继续把重点放在“又加一个过滤器”或“让 AI 再解释一次”，而要把工作拆成三个层次不同、可分别验证的贡献。

---

## 2. 新的总主线

建议将论文主线收敛为：

```text
跨层知识建模 → 智能路径发现 → 可信证据判定
```

对应系统原型：

```text
CloudDB-PathDetect
= KG Construction
→ Path Reasoning
→ Evidence Acquisition
→ Verification
→ Explanation / Repair
```

这样原来的 Demo 不再是一个孤立展示系统，而是贯穿三项方法工作的工程载体。

## 3. 三项推荐创新点

### 创新点一：跨层云数据库安全时序证据知识图谱构建

#### 3.1 解决的问题

现有 IAM 图、云资产图通常停留在：

```text
Identity → Permission → Resource
```

你的任务需要扩展为：

```text
External / Network
→ Identity / Role / Policy
→ Permission / Action
→ DBInstance / Secret / Service
→ Database / Table / Column
→ SensitiveData
→ AuditEvent / RiskFinding / Control
```

核心问题是：如何把云配置、IAM、网络、数据库对象、敏感数据识别结果、审计日志统一表示为一张可计算、可追溯、可更新时间的证据图。

#### 3.2 方法定义

建议把基本事实从普通三元组升级为带时间、来源和证据状态的扩展事实：

```text
q = (h, r, t, τ, ρ, s)
```

含义：

- `h`：主语实体；
- `r`：规范化关系；
- `t`：宾语实体；
- `τ`：时间戳或时间区间；
- `ρ`：证据来源 / provenance；
- `s`：证据状态，取值为 `Supported / Contradicted / Unknown`。

也可以写成更通用的时序证据边：

```text
edge = (subject, relation, object, time, source, confidence)
```

从而定义：

```text
G_T = (V, E, τ, λ)
```

其中：

- `V` 是跨层实体集合；
- `E` 是带时间与来源的证据边；
- `τ` 管理时间切片；
- `λ` 管理实体类型、边类型和证据类型。

#### 3.3 真正的算法/工程工作量

这一项不能写成“把 JSON 存进图”。应强调以下工作：

1. **多源实体统一**

   ```text
   φ: x_raw → e_canonical
   ```

   解决同一数据库实例、角色、密钥、服务在 Terraform、IAM、网络配置、审计日志中的身份统一问题。

2. **关系规范化**

   ```text
   ψ(r_raw) → r_KG
   ```

   把原始 API 字段、日志字段、策略动作统一映射为有限关系集合。

3. **敏感数据层次传播**

   ```text
   Column → Table → Database → DBInstance
   ```

   将字段级敏感标签向表、库、实例聚合，形成高敏终点。

4. **证据来源与时间保留**

   每条边都能追溯：

   ```text
   Triple / Edge → Evidence → Source
   ```

5. **证据状态建模**

   区分：

   - `Supported`：有证据支持；
   - `Contradicted`：有明确反证；
   - `Unknown`：当前不可见或未查询。

#### 3.4 可复用现有工作

| 现有内容 | 新定位 |
|---|---|
| 8 类节点、10 类边 | KG Schema 初版 |
| 60+20 个案例 | 初始评测切片 |
| CloudGoat 数据 | 外部靶场来源 |
| 风险图代码 | 跨层时序证据 KG 的 V0.1 |
| `src/graph` | 图构建与约束层基础 |
| `src/data_gen` | 数据构造与标注基础 |

#### 3.5 实验设计

可以设计三组实验：

1. **图构建质量实验**
   - 实体映射准确率；
   - 关系映射准确率；
   - 图结构合法率；
   - 时间切片完整率；
   - 数据源接入覆盖率。

2. **证据增强收益实验**
   - 仅 IAM 图；
   - IAM + 网络 + 资源图；
   - IAM + 网络 + 数据库对象 + 日志 + 敏感标签的完整证据图。

   指标：Path Recall@K、终点发现率、Exact Path Hit。

3. **高敏数据库终点识别实验**
   - `rds://pii_table`；
   - `secret://db_password`；
   - `s3://sensitive_bucket`；
   - `log://db_access_event`。

#### 3.6 论文中的贡献表达

可以写为：

> 提出一种面向云数据库高敏数据暴露侦测的跨层时序证据知识图谱构建方法，将 IAM、网络、数据库对象、敏感数据标签、审计日志和控制项统一编码为带时间、来源和证据状态的扩展事实，并支持实体统一、关系规范化与敏感性层次传播。

### 创新点二：基于规则学习与语义约束的高敏数据暴露路径推理

#### 3.1 解决的问题

现有系统把约束 DFS 当成主要算法，这不够。

后续应该重新定位：

```text
DFS 只是执行器，不是最终算法贡献。
```

真正的问题是：

> 在跨层证据图上，如何自动发现“最值得调查”的高敏数据暴露路径，而不是枚举所有路径后再反复过滤。

#### 3.2 推荐方法结构

建议采用三层结构：

```text
规则学习 → 语义约束 → 优先级路径搜索
```

#### 3.3 第一层：规则学习生成候选路径模式

使用 AnyBURL / TILP 风格的规则学习，从图中学习路径规则，例如：

```text
canConnect(x, y)
∧ hasPermission(z, y)
∧ contains(y, d)
∧ Sensitive(d)
⇒ PotentialExposure(x, d)
```

规则集合：

```text
R = {r_1, r_2, ..., r_m}
```

每条规则带有：

```text
Conf(r), Support(r)
```

这样路径模式不再完全手写，而是从图和样本中学习得到。

#### 3.4 第二层：硬语义约束保证合法性

定义合法路径语法：

```text
P ∈ P_valid ⇔ Grammar(P) = 1
```

例如合法链路：

```text
Network → Identity → Permission → DBInstance → DBObject → SensitiveTag
```

非法链路直接剪枝。

原来的类型约束 DFS 可以保留，但要重新定位为：

```text
语义约束执行层 / Grammar-based pruning
```

#### 3.5 第三层：候选路径优先级搜索

定义路径优先级：

```text
Priority(P) = α S_rule(P)
            + β S_target(P)
            + γ S_evidence(P)
            - η Cost(P)
```

含义：

- `S_rule(P)`：规则置信度；
- `S_target(P)`：敏感目标价值；
- `S_evidence(P)`：当前证据完整度；
- `Cost(P)`：继续调查成本，如路径长度、查询代价、未知边数量。

每轮选择：

```text
P* = argmax_{P ∈ P_t} Priority(P)
```

这就把“搜索路径”从穷举问题改成了预算约束下的优先调查问题。

#### 3.6 与 NBFNet / A*Net 的关系

如果要增强算法感，可以把路径扩展写成 NBFNet 风格的消息传播：

```text
h_{t+1}(v) = AGG_{(u,r,v)∈E}(MSG(h_t(u), r, q))
```

再引入 A*Net 风格的优先级函数：

```text
π_t(v | q) = softmax(gθ(h_t(v), q, Δt_v))
```

只展开 Top-ρ 的节点或边，降低大图上的扩展成本。

但短期落地不建议一开始就训练完整神经模型。更现实的版本是：

```text
AnyBURL 规则学习
+ 语义约束 DFS
+ 手工/可学习优先级评分
```

#### 3.7 实验设计

对比方法：

| 方法 | 定位 |
|---|---|
| 普通 DFS | 弱基线 |
| 类型约束 DFS | 现有方法基线 |
| 完整约束 DFS | 当前系统 V0.1 |
| AnyBURL 规则推理 | 规则学习基线 |
| 人工启发式排序 | 手工优先级基线 |
| 规则 + 语义约束 + 优先级搜索 | 你的方法 |
| NBFNet / A*Net | 可选强基线 |

指标：

- Path Recall@K；
- Precision@K；
- MRR；
- Exact Path Match；
- 枚举路径数；
- 平均扩展节点数；
- 平均调查成本；
- 单位时间发现有效路径数；
- 查询预算下的路径召回率。

#### 3.8 论文中的贡献表达

可以写为：

> 提出一种基于规则学习与语义约束的高敏数据暴露路径推理方法，利用知识图谱规则学习生成候选暴露模式，结合云安全语义语法进行合法性剪枝，并通过证据感知优先级函数在有限查询预算下优先发现高价值暴露路径。

### 创新点三：不完备证据下的三值验证与最小证据解释

#### 3.1 解决的问题

当前 GateScore 最大的问题是：

> 它把“路径是否成立”和“风险严重度排序”混在一起了。

后续建议重新定位：

```text
三值验证器：负责证明路径是否成立
GateScore / RiskScore：只负责风险严重度排序
```

这样可以避免老师继续批评“你只是又用一个公式过滤一次”。

#### 3.2 三值证据逻辑

定义每个关键证据维度：

```text
z_i ∈ {T, F, U}
```

含义：

- `T`：事实支持；
- `F`：明确反证；
- `U`：证据未知。

路径状态：

```text
State(P) =
  Invalid,      if ∃ z_i = F
  Insufficient, if no z_i = F and ∃ z_j = U
  Valid,        if ∀ z_i = T
```

这正好把你已有的“反证 / 缺证实验”理论化。

#### 3.3 SMT / 约束验证替换简单 Gate

将路径成立条件编码为逻辑公式：

```text
Φ_P = Φ_network
    ∧ Φ_permission
    ∧ Φ_target
    ∧ Φ_sensitivity
    ∧ Φ_temporal
```

求解：

```text
SAT(Φ_P)
```

结果解释：

| 求解结果 | 路径状态 |
|---|---|
| UNSAT | 路径不成立 / Invalid |
| UNKNOWN / missing evidence | 证据不足 / Insufficient |
| SAT | 路径成立 / Valid |

再区分风险类型：

```text
SAT + AuditEvidence     → ObservedRisk
SAT + no AuditEvidence  → PotentialExposure
```

这样 GateScore 可以保留为：

```text
RiskSeverity(P)
```

而不是作为路径成立性的证明器。

#### 3.4 主动查询策略

当路径状态为 `U / Insufficient` 时，不应全量查询，而应选择最有价值的问题：

```text
q* = argmax_{q ∈ Q} [ΔRisk(q) + β ΔUncertainty(q) - γ Cost(q)]
```

更容易实现的启发式版本：

> 优先询问出现在最多候选路径交汇处、且能最大区分 T/F 的未知边。

示例查询：

- Role A 是否能 `AssumeRole` 到 Role B？
- Function F 是否读取过 Secret S？
- SecurityGroup G 是否允许公网访问 RDS 端口？
- Table T 是否包含 PII 字段？
- AuditLog 中是否存在访问事件？

#### 3.5 最小证据见证集

定义：

```text
W* = argmin_{W ⊆ E(P)} |W|
     s.t. Verifier(P, W) = Valid
```

含义：

> 在所有证据中寻找能够证明这条暴露路径成立的最小证据集合。

系统输出不再是几十条边，而是：

```text
证明该路径成立只需要这 5 条关键证据。
```

这非常适合作为“证据约束智能体”的核心贡献。

#### 3.6 最小修复集

可以进一步定义最小修复：

```text
min Σ c_i x_i
```

约束：对每一条危险路径 `P_j`，至少有一个修复动作命中它：

```text
Σ_{i ∈ Hit(P_j)} x_i ≥ 1
```

修复动作示例：

- 显式 deny 某权限；
- 移除某 trust relation；
- 收紧 secret access；
- 删除公网网络边；
- 开启 TDE / 审计；
- 收敛数据库用户权限。

#### 3.7 可复用现有工作

| 现有内容 | 新定位 |
|---|---|
| 五维证据 | 三值证据维度初版 |
| GateScore | RiskSeverity 排序器 |
| 反证/缺证实验 | 三值验证实验基础 |
| 七类工具 | 主动查询执行器 |
| 缺口驱动查询 | 主动查询策略 V0.1 |
| LLM 归因 | 解释层，不参与判定 |

#### 3.8 实验设计

1. **验证正确性**
   - T/F/U 分类准确率；
   - 误报率；
   - 漏报率；
   - 反证识别率；
   - 缺证识别率。

2. **主动查询效率**
   - 平均查询数；
   - 单位查询发现真路径数；
   - 查询预算下的召回率；
   - 与全量查询、固定顺序查询、随机查询对比。

3. **最小证据解释质量**
   - 平均证据集大小；
   - 最小证据覆盖率；
   - 人工可读性评分；
   - 解释冗余率。

4. **最小修复质量**
   - 补丁大小；
   - 修复后剩余风险；
   - 误杀率；
   - 运行时间。

#### 3.9 论文中的贡献表达

可以写为：

> 提出一种面向部分可见云数据库暴露路径的不完备证据验证方法，将路径证据建模为 T/F/U 三值逻辑，通过约束求解区分路径成立、明确反证与证据不足，并进一步生成最小证据见证集和最小修复集，提高路径判定的可信性与可解释性。

## 4. 与相关工作的定位关系

调研报告显示，国外已有很多局部能力很强的系统，但没有一个完全覆盖你的任务。

| 方向 | 代表工作 | 强项 | 缺口 |
|---|---|---|---|
| 云 IAM / 多步攻击检测 | TAC, CloudLens, PMapper, USENIX IAM Model Checking | IAM 语义、权限传播、多步路径 | 不聚焦数据库高敏终点，缺少数据库对象层和日志证据层 |
| 形式化验证 | Zelkova, Access Analyzer | 策略语义验证、SMT 求解 | 主要面向资源策略，不覆盖完整跨层暴露链 |
| 自动修复 | IAMPERE, IAM-Deescalate | MaxSAT 修复、最小 deny patch | 主要聚焦 IAM PE，不覆盖数据库敏感数据链路 |
| 图推理 | AnyBURL, NBFNet, A*Net, ULTRA, TILP | 路径推理、规则学习、可扩展搜索 | 原生不理解云 IAM / 数据库安全语义 |
| 工程靶场 | CloudGoat, IAM Vulnerable, Pathfinding Labs, Stratus, Pacu | 可复现环境、攻击日志、靶场任务 | 缺少统一研究建模与高敏数据库终点评测 |

论文可以这样回应：

> 现有工作要么强在云权限确定性分析，要么强在图上的高效路径推理，要么强在靶场与工程复现；本文的工作是在云数据库高敏数据暴露路径这一具体任务下，将跨层时序证据建模、智能路径推理和不完备证据验证统一起来。

## 6. 建议停止继续扩散的方向

当前阶段建议暂停：

- 暂停把 Benchmark 当核心创新；
- 暂停“大模型微调”作为主线；
- 暂停多智能体包装；
- 暂停随意加入 GraphRAG；
- 暂停继续堆叠新的 Gate / Filter；
- 暂停只做可视化 Demo。

接下来只沿着三条线做深：

```text
知识图谱建模 → 路径推理 → 可信验证
```

每一项都要做到：

```text
问题定义 + 方法公式 + 代码实现 + Baseline + 消融实验 + 结果分析
```

## 8. 推荐短期落地路线

### 第一阶段：修正论文结构和现有代码定位

## 10. 最小可毕业版本

如果时间有限，建议最小版本做成：

1. **KG 工作**：不做完整 Cartography 级采集器，只做统一 Schema + 样本转换 + provenance/time/status；
2. **路径推理工作**：AnyBURL + 约束 DFS + Priority 排序，不训练大型图神经网络；
3. **验证工作**：三值逻辑 + 启发式主动查询 + 最小证据集，最小修复作为增强项；
4. **系统工作**：保留现有 Web/HTML 展示，但改成展示三项方法链路，而不是展示“一个 Demo”。

这样可以形成足够清晰的毕业论文工作量：

```text
数据建模有工作量；
路径推理有算法；
证据验证有形式化；
系统展示有闭环。
```

## 11. 最重要的重构原则

后续所有新增工作都要问自己：

> 它属于 KG 建模、路径推理、还是可信验证？

如果不属于这三条线，就先不要做。

最终论文要避免变成：

```text
Benchmark + Demo + AI解释 + GateScore
```

而应变成：

```text
跨层时序证据 KG
+ 规则学习与语义约束路径推理
+ 三值验证与最小证据解释
+ CloudDB-PathDetect 原型系统
```

这是更能回应中期批评、也更容易支撑毕业答辩的结构。
