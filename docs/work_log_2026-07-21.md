## 一、C1 异构云证据语义化方法完善

### 1.1 证据语义 Schema 固化

完成 6 维证据边定义：

```text
e = (u, r, v, status, source, time, confidence, query_cost, raw_evidence)
```

其中 `status ∈ {Supported, Contradicted, Unknown}`，显式区分三类证据状态。

**成果**：字段覆盖率 100%，SHACL-style 校验规则 R1–R15 全部通过。

### 1.2 三值路径验证器（T/F/U Verifier）

实现 6 维三值验证器，对路径的 `entry / reach / perm / target / sense / temporal` 进行判定：

- **Valid**：所有维度均为 Supported
- **Invalid**：任一维度存在 Contradicted
- **Insufficient**：无 Contradicted，但存在 Unknown

**成果**：676 路径标签，准确率 99.56%。

### 1.3 反证/缺证/时序变体构造

实现三类可控变体生成：

| 变体类型 | 扰动策略 | 样本级标签 |
|---|---|---|
| `missing` | 关键硬证据边标记为 Unknown | Insufficient |
| `refuted` | 关键硬证据边标记为 Contradicted | Invalid |
| `temporal_conflict` | 注入时序冲突标记 | Invalid |

**成果**：207 变体样本，覆盖全部 6 类标签。

## 二、C2 反证感知路径搜索与排序方法

### 2.1 RefuteAwareBeamSearch 算法

核心思想：在路径扩展阶段即引入证据状态感知，而非事后排序。

**边评分函数**：

```text
score(e) =
  - large_penalty,  if status(e)=Contradicted or temporal_conflict(e)
  - medium_penalty, if status(e)=Unknown
  positive_score,  if status(e)=Supported
```

**路径优先级**：

```text
Priority(P) = evidence_score(P) + target_bonus(P) - query_cost(P) - path_length_penalty(P)
```

### 2.2 与 GateScore 的关系

显式拆分职责：

| 组件 | 职责 |
|---|---|
| T/F/U Verifier | 判定路径是否成立（Valid / Invalid / Insufficient） |
| GateScore | 对已成立路径进行风险严重度辅助排序 |

### 2.3 实验结果

**语料规模**：313 样本（含 SDDP 复杂切片），676 路径标签，5456 边。

**C2 搜索对比**（313 样本）：

| 方法 | R@1 | R@3 | R@5 | MRR | FPR |
|---|---:|---:|---:|---:|---:|
| Plain DFS + GateScore | 0.1057 | 0.1886 | 0.2714 | 0.3877 | 0.0000 |
| Type DFS + GateScore | 0.1057 | 0.1886 | 0.2714 | 0.3877 | 0.0000 |
| Full constrained + GateScore | 0.1057 | 0.2171 | 0.3714 | 0.3571 | 0.0000 |
| **RefuteAwareBeamSearch** | **0.2429** | **0.6514** | **0.6743** | **0.5044** | **0.0000** |

**相对提升**（以 Full constrained + GateScore 为基线）：

| 指标 | 基线 | RefuteAwareBeamSearch | 相对提升 |
|---|---:|---:|---:|
| R@3 | 0.2171 | 0.6514 | +199.8% |
| R@5 | 0.3714 | 0.6743 | +81.6% |
| MRR | 0.3571 | 0.5044 | +41.2% |

**结论**：RefuteAwareBeamSearch 在部分可见、反证/缺证混杂条件下，仍能实现高召回、零误报的暴露路径侦测。

## 三、SDDP 真实数据安全平台证据接入

### 3.1 SDDP 切片转换器

实现 `scripts/build_sddp_evidence_slice.py`，将本地导出的 SDDP/DSC JSON 转换为 CloudDB 语义证据图格式。

**输入文件**：
- `data_instance_source.json` - 资产实例
- `sys_data_limit.json` - 授权与连通性
- `dsc_identify_task_asset.json` - 识别任务绑定
- `data_objects.json` - 数据库 / 表 / 列 / 敏感规则
- `sls_results.json` - 底层识别结果证据

**映射规则**：
- `data_instance_source` → DBInstance 节点
- `sys_data_limit.check_status` → can_connect 边（3=Supported, 4=Contradicted, -1=Unknown）
- `DescribeDataObjects` → DBInstance → Database → Table → Column → SensitiveTag 层级结构

### 3.2 复杂真实切片生成

实现 `scripts/generate_complex_sddp_slice.py`，生成模拟真实生产环境的复杂证据切片：

**规模**：152 节点，195 边，5 条暴露路径

**节点类型分布**：
- Network（VPC / Subnet / Security Group）
- Identity（User / Role / Policy）
- DBInstance（TABLE / LCOLUMN / TSDB / LSEARCH）
- DBObject（Database / Table / Column）
- SensitiveTag（身份证号 / 手机号 / 银行卡号 / 密码 / 地址 / 邮箱）
- AuditEvent（access / query / export / modify）

**证据状态分布**：
- Supported：147 边
- Unknown：32 边
- Contradicted：16 边

**结论**：C1 语义证据图可承载真实云安全平台证据，并通过可控威胁注入生成半真实评测集。
