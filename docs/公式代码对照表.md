## 第一层：基础概念（第 3 章）

### 环境快照六元组 $S_t = (\mathcal{A}, \mathcal{N}, \mathcal{I}, \mathcal{D}, \mathcal{L}, \mathcal{C})$

| 项目 | 说明 |
|------|------|
| **大白话** | 把云环境拍个"快照"：资产层(数据库/表/字段)、网络层(VPC/安全组)、身份权限层、敏感数据分布层、审计日志层、治理状态层 |
| **实现** | 定义数据类：`assets, network, identity, sensitive_data, audit_logs, controls` |
| **难度** | 几行逻辑 |
| **答辩语** | 云数据库威胁是多维耦合的，必须在六个维度上统一建模才能支持路径级分析 |

### 三层敏感性评分 

**字段层**: $S_{field}(f) = level(f) \times confidence(f)$

| 项目 | 说明 |
|------|------|
| **大白话** | 敏感度 = 敏感等级(L1/L2/L3/L4) × 识别置信度(0-1) |
| **例子** | 身份证号(L4) × 99% = 0.99 × 4 = 3.96 |
| **难度** | 一行代码 |

**表层**: $S_{table}(t) = \max_{f} S_{field}(f) + \lambda_1 \cdot |HighSens(t)| + \lambda_2 \cdot \frac{|Sens(t)|}{|Fields(t)|}$

| 项目 | 说明 |
|------|------|
| **大白话** | 表分数 = 最敏感字段 + 高敏字段数量修正 + 高敏占比修正 |
| **为什么** | 避免"一个L4埋在200列"和"50列中30列都是L4"混淆 |
| **难度** | 几行逻辑 |

**实例层**: $S_{instance}(i) = \max_t S_{table}(t) + \mu_1 \cdot |HighTables| + \mu_2 \cdot |ExposedTables|$

| 项目 | 说明 |
|------|------|
| **大白话** | 实例分数 = 最敏感表 + 高敏表数量 + 已暴露表数量 |
| **难度** | 几行逻辑 |

## Agent 循环核心（§4.1 — 新架构核心，全文最大改造）

> EIC-Agent 从"固定八阶段流水线"改造为"假设驱动的 Agent 循环"。**算法 4.1、Gate-Score 定义、所有定理证明一字未改，只是重新定位。** 全文定位词："证据表达者" → "证据调查者与表达者"。

### 信念状态（POMDP） $\mathcal{S}_t = (\mathcal{H}_t, \mathcal{E}_t, \mathcal{B}_t)$

| 项目 | 说明 |
|------|------|
| **大白话** | Agent 内部状态三元组：$\mathcal{H}_t$ 当前活跃路径假设集、$\mathcal{E}_t$ 已采集工具证据库、$\mathcal{B}_t$ 每个假设的当前 EIC 评估信念 |
| **关键** | 信念状态是 Agent 决策的**唯一依据**；所有动作选择/剪枝/终止都基于 $\mathcal{S}_t$，而非外部隐状态 |
| **答辩语** | 环境快照六元组是"世界状态"（S1），$\mathcal{S}_t$ 是 Agent 对世界的"信念"，二者分离——这是把固定流水线换成闭环迭代的形式化基础 |

### 动作空间与策略

$$\mathcal{A} = \{\texttt{query}, \texttt{expand}, \texttt{prune}, \texttt{confirm}, \texttt{terminate}\}, \quad \pi: \mathcal{S} \to \mathcal{A}, \; a_t \sim \pi(\cdot \mid \mathcal{S}_t)$$

| 动作 | 语义 | 对应旧要素 |
|------|------|-----------|
| query(h,d,tool) | 对假设 h 的维度 d 调工具取证 | S5 |
| expand(h) | 在终点邻域延伸新假设（内部调算法 4.1） | S4 |
| prune(h) | 剔除低优先级假设 | 新（原隐含） |
| confirm(h) | 确认为暴露路径入结果集 $\mathcal{R}$ | S6 |
| terminate | 输出风险排序与报告 | S7-S8 |

| 项目 | 说明 |
|------|------|
| **DIE 偏置** | Discover(假设生成偏置)/Investigate(证据采集偏置)/Explain(终止输出偏置)——不是硬状态机，是策略 $\pi$ 的先验偏好，信念可在三者间**回退**（固定流水线做不到） |
| **答辩语** | S1-S8 不是线性执行序列，而是状态/动作空间构成要素；这是"固定八阶段"→"假设驱动循环"的关键重新定位 |

### 信息增益 — 主循环决策核心（§4.6）

$$d^* = \arg\max_{d:\, \varepsilon_d < \tau_d} \text{IG}(d \mid P, G), \qquad \widetilde{\text{IG}}(d) = (\tau_d - \varepsilon_d(P)) \cdot w_d$$

| 项目 | 说明 |
|------|------|
| **大白话** | Agent 每步选信息增益最大的未通过维度去 query；增益耗尽则 prune/confirm/terminate |
| **定位升级** | IG 从"补证机制"提升为"主循环每步动作选择的核心决策函数" |
| **答辩语** | 让 Agent 主动选查询目标而非僵硬走固定阶段，是 B6(主动调查) vs B7(固定流水线) 的本质差异 |

## 第二层：路径搜索（第 4.2 节）

### 约束路径搜索算法

```python
def constrained_path_search(graph, entry_nodes, target_nodes, type_matrix, max_length=8):
    paths = []
    for start in entry_nodes:
        stack = [(start, [start], None, {start})]
        while stack:
            node, path, prev_type, visited = stack.pop()
            
            # 检查是否到达目标
            if node in target_nodes and 4 <= len(path) <= max_length:
                paths.append(path)
            
            if len(path) >= max_length:
                continue
            
            for neighbor in graph.neighbors(node):
                if neighbor in visited:
                    continue  # 剪枝1：简单路径
                
                edge_type = graph.edge_type(node, neighbor)
                
                if prev_type and not type_matrix[prev_type][edge_type]:
                    continue  # 剪枝2：类型合法性
                
                if not type_compatible(graph.node_type(neighbor), edge_type):
                    continue  # 剪枝3：端点兼容性
                
                stack.append((neighbor, path + [neighbor], edge_type, visited | {neighbor}))
    
    return dedup(paths)
```

| 项目 | 说明 |
|------|------|
| **难度** | 需要框架支持（Neo4j/NetworkX） |
| **定位（新）** | $C(G)$ 是 **Agent 循环初始假设集 $\mathcal{H}_0$ 的供给**（假设生成器），**不是最终检测结果**；循环中 expand 动作在受限子图上重调本算法延伸假设 |
| **答辩语** | 三重剪枝将复杂度从 $O(b^8)$ 降至 $O((b×0.18)^8)$，6 个数量级加速；定理 4.1 完备性相应解释为"假设生成完备性"——漏检只可能是证据不足，而非未搜索到 |

## 第三层：证据约束（第 4.3 节）

### 五个证据评估函数

| 维度 | 公式 | 含义 | 聚合方式 | 代码难度 |
|------|------|------|---------|---------|
| entry | $\varepsilon_{entry} = \omega_1 \cdot exposure + \omega_2 \cdot external + \omega_3 \cdot credential$ | 入口暴露度 | 加权平均 | 需要API |
| reach | $\varepsilon_{reach} = \prod r(v_i, v_{i+1})$ | 网络可达性 | **乘积** | 需要API |
| perm | $\varepsilon_{perm} = \min(\text{conf})$ | 权限覆盖 | **最小值** | 需要API |
| target | $\varepsilon_{target} = S_{target}/S_{max}$ | 目标价值 | 比率 | 一行 |
| sense | $\varepsilon_{sense} = \max(\text{confidence} × \text{level})$ | 敏感数据确认 | **最大值** | 一行 |

**关键设计**：
- `reach` 用乘积：链式可达，一断全断
- `perm` 用最小值：权限链的"最短板"决定整体
- `sense` 用最大值："有一个高敏数据点就够了"

### EIC 验证算子 $\text{EIC}(P) = \text{Gate}(P) \times \text{Score}(P)$

```python
def evaluate_eic(path, graph, thresholds):
    # 五维证据评估
    eps = {
        'entry': evaluate_entry(graph, path[0]),
        'reach': evaluate_reach(graph, path),
        'perm': evaluate_perm(graph, path),
        'target': evaluate_target(graph, path[-1]),
        'sense': evaluate_sense(graph, path)
    }
    
    # Gate：硬约束检查（一票否决）
    hard_dims = ['entry', 'reach', 'perm']
    gate = 1
    for d in hard_dims:
        if eps[d] < thresholds[d]:
            gate = 0
            break  # 快速短路
    
    # Score：软约束加权几何平均
    score = 1.0
    weights = {'entry': 0.2, 'reach': 0.3, 'perm': 0.2, 'target': 0.15, 'sense': 0.15}
    for d, w in weights.items():
        score *= (eps[d] ** w)
    
    eic = gate * score
    
    return eic, {
        'gate': gate,
        'score': score,
        'evidence': eps
    }
```

| 项目 | 说明 |
|------|------|
| **Gate** | $\prod \mathbb{1}[\varepsilon_d \geq \tau_d]$ for hard dims，任何一个失败则 Gate=0 |
| **Score** | $\prod \varepsilon_d^{w_d}$，几何平均避免"单一维度极端值"欺骗 |
| **难度** | 需要框架支持 |
| **答辩语** | Gate 实现"一票否决"快速筛选，Score 在通过后进行精细排序；分离硬约束和软约束使判定可审计 |

**EIC 在 Agent 循环中的三重角色**（新架构，§4.3）：① **剪枝准则**（Gate=0 且 $\widetilde{IG}<\delta_{IG}$ → prune）；② **补证触发器**（Gate=0 但 $\widetilde{IG}\geq\delta_{IG}$ → query 最大增益维度 $d^*$）；③ **确认准则**（Gate=1 且 Score≥$\theta_{high}$ → confirm）。EIC 从"一次性终判"演化为"逐步逼近"的迭代过程。

## 第四层：理论性质（第 4.3.4 节）

### 定理 4.1：搜索完备性
所有满足约束 (C1)-(C3) 的路径都能被算法 4.1 完整枚举 ✓

### 定理 4.2：单调性
若 $G' \supseteq G$（添加证据），则 $\mathrm{EIC}(P; G') \geq \mathrm{EIC}(P; G)$

| 含义 | 用途 |
|------|------|
| 增加证据永远不会降低路径分数 | 支撑搜索剪枝与增量更新；**并保证 Agent 循环信念单调收敛**（query 只增证据不删，$\mathcal{B}_{t+1}(h)\geq\mathcal{B}_t(h)$ 逐点成立）→ 循环有限步终止 |

### 定理 4.3：零元素性
若任何硬约束维度未达阈值，则 $\mathrm{EIC} = 0$

| 含义 | 用途 |
|------|------|
| 硬约束失守即否决 | 形式保证了"一票否决"逻辑 |

### 定理 4.4：假设空间收缩
$|H_{EIC}| \leq |H| \cdot \prod_d \mathbb{P}(\varepsilon_d \geq \tau_d)$

| 含义 | 用途 |
|------|------|
| 每个硬约束乘性收缩可幻觉空间 | 理论解释 EIC 从 16% 幻觉率降至 6%；**Agent 循环视角下逐维收缩**：每步 query 将一维冻结为通过/未通过，LLM 可幻觉空间逐维收缩 |

## 第五层：排序与工具（第 4.4-4.5 节）

### 风险排序模型

$$\text{Risk}(P) = \sigma\left(\sum_d \beta_d \log\frac{\varepsilon_d + \epsilon_0}{1-\varepsilon_d + \epsilon_0} + \beta_0\right)$$

| 项目 | 说明 |
|------|------|
| **大白话** | 把五维证据通过对数几率变换映射到 (-∞, +∞)，再用 sigmoid 还原为 (0,1) 区间的风险分数 |
| **好处** | 支持参数学习；与 NDCG 排序指标天然兼容；能精细区分高风险路径 |
| **实现** | Python：`scipy.special.expit(logits)` |
| **难度** | 一行代码 |

### 7 个工具接口

| 工具 | 输入 | 输出 | 何时调用 |
|------|------|------|---------|
| T1: GraphPathSearch | 入口集、目标集 | 候选路径集 $C(G)$ | 阶段A（候选生成） |
| T2: NetworkCheck | 节点对 $(u,v)$ | 可达布尔、置信度、证据 | 阶段B（硬约束剪枝）优先 |
| T3: PermissionCheck | 身份、资源 | 权限类型、置信度 | 阶段B（次优先） |
| T4: SensitiveDataQuery | DB 对象 | 敏感标签、等级、置信度 | 阶段C（软约束补强） |
| T5: AuditLogQuery | 身份、对象、时间窗 | 事件流、异常评分 | 阶段C |
| T6: ControlStatusCheck | DB 对象 | 控制状态、防护强度 | 阶段C（可选） |
| T7: EvidenceValidator | 路径 | EIC 状态、得分、缺失维度 | 最终判定 |

**先验策略 $\pi_0$ + 主动偏离**（§4.5.2，新）：上表"阶段 A/B/C"即 $\pi_0$ 的三阶段（候选生成→硬约束剪枝→软约束补强），是**安全默认**。Agent 在信念 $\mathcal{S}_t$ 显示某维度证据不足且信息增益显著时**主动偏离** $\pi_0$：

$$\widetilde{IG}(a_{deviate}) - \widetilde{IG}(a_{\pi_0}) > \lambda \cdot [\text{Cost}(a_{deviate})-\text{Cost}(a_{\pi_0})]$$

$\pi_0$ 给期望成本下界，下层信念给主动优化，两层决策结构。

### 图验证反馈对齐 (GV-FA)

关键创新：用**图 + EIC 算子**充当自动裁判，代替人工标注

```python
# SFT 轨迹自动验证（6 条规则，R6 为新增）
def verify_sft_trajectory(trajectory, graph):
    checks = {
        'R1_path_legality': all(node in graph.V for node in trajectory.path),
        'R2_evidence_completeness': has_hard_evidence(trajectory),
        'R3_ranking_consistency': ndcg_at_3(trajectory) >= 0.85,
        'R4_remediation_match': remediation_matches_root_cause(trajectory),
        'R5_schema_validity': is_valid_json(trajectory.output),
        'R6_trajectory_validity': all(ig(a_i) >= delta_IG or a_i in pi_0
                                      for a_i in trajectory.actions)
        # R6（新增）：每步动作信息增益达标或属于先验策略必经步骤，剔除无意义查询
    }
    return all(checks.values())

# DPO 偏好对自动注入（7 类错误）
def generate_negative_samples(gold_response, graph):
    errors = [
        'path_hallucination',        # E1：删除存在的边或引入虚假边
        'principal_mismatch',        # E2：替换权限链中的无关主体
        'evidence_fabrication',      # E3：引用不存在的日志事件
        'target_demotion',          # E4：替换为非敏感目标
        'risk_misjudgment',         # E5：错判风险等级
        'vague_remediation',        # E6：空泛的处置建议
        'over_claim'                # E7：Gate=0 仍输出 Observed_Risk
    ]
    # 对每个错误类型生成负样本 → 验证确实劣于 gold_response
    return [perturb(gold_response, e) for e in errors]
```

| 项目 | 说明 |

| **优势** | 无需人工标注；错误类型丰富且可控；与 EIC 理论一致 |
| **难度** | 需要框架支持 |

## 答辩常见问题速查表

| 问题 | 答辩要点 |
|------|--------|
| **为什么要分五个维度？** | 攻击链条的因果性：entry(入口) → reach(网络) → perm(权限) → target(目标) + sense(数据)，每个都必须满足 |
| **为什么 reach 用乘积、perm 用最小值、sense 用最大值？** | 反映底层现实：reach 是链式物理通过(一断全断)；perm 是逻辑授权(最弱环定值)；sense 是数据确认(一点即够) |
| **Gate 和 Score 为什么要分开？** | Gate 做"一票否决"的快速筛选，Score 做精细排序；分离使判定可审计且支持阈值动态调整 |
| **为什么用加权几何平均而不是算术平均？** | 几何平均保证任何维度的极低值都显著拉低总分，反映"多维证据协同必要"；算术平均会被单一高值欺骗 |
| **图验证反馈 vs 传统 RLHF？** | RLHF 依赖人工标注，在专业领域成本极高；图验证直接用 EIC 算子自动判定偏好对，无需人工，错误类型系统化 |
| **为什么 8 跳的长度上限合理？** | 基于攻击经济学：8 跳已涵盖典型真实路径；更长的路径组合爆炸且攻击者实际执行代价过高 |
| **单调性定理的实用意义？** | 支撑搜索剪枝和增量更新的正确性：发现新证据永远不会降低已判定的风险分数 |
| **为什么是"证据完整性"而不是"直接风险打分"？** | 安全运营的合规要求（ISO27001、SOC2）：每个判定都必须有可审计的原始证据支撑，不能是黑盒的模型输出 |
| **S1–S8 还是固定八阶段流水线吗？** | 不是。新架构下 S1–S8 是状态/动作空间的构成要素，端到端是假设驱动的 Agent 循环；算法 4.1、Gate-Score、定理证明一字未改，只是重新定位为循环中的角色 |
| **实验数据是真实跑出来的吗？** | 核心演算部分是：cloud_db_pathbench 原型已在 5 案例 60 路径上确定性跑通，5/5 类型匹配，Gate·Score 真实分布 0.117–0.933；主效果对比表标 † 者为预期值，待 MVP 第 2–4 周补全 B1–B5 与轨迹级指标 |
| **B6 主动调查 vs B7 固定流水线区别？** | B7 禁用主动偏离、强制遵循 π₀；B6 基于信念状态 $\mathcal{S}_t$ 与信息增益主动选查询维度。路径准确性接近（PA 差≈0.01），但 B6 在证据效率(EQP)/上下文经济(CRR)/收敛步数(CS)上显著更优 |

## 快速查询：哪些不用自己实现

| 项目 | 为什么不用自己实现 |
|------|------------------|
| **SFT/DPO 损失函数** | 用 transformers/TRL 库直接调用，已经过优化和验证 |
| **LoRA 训练** | 用 peft 库，参数高效微调标准实现 |
| **NDCG 指标** | sklearn.metrics 或 ranx 库，标准信息检索指标 |
| **IAM 策略评估** | 各云厂商有官方 SDK（boto3/azure-sdk），原生支持策略模拟 |
| **JSON Schema 验证** | jsonschema 库，标准验证框架 |

## 总结：方法的"三位一体"

```
CloudDB-PathBench (基准)
        ↓
   定义"问题"和评测
        ↓
     EIC-Agent (推理)
        ↓
   "证据约束"限制 LLM，使输出可审计
        ↓
    GV-FA (对齐)
        ↓
  用图验证代替人工标注，小模型能力对标大模型
```

整个系统的核心哲学：**"不是让 LLM 承担风险判定（那样会有幻觉），而是让 LLM 负责证据调查与表达（假设生成/动作选择/证据解读），由确定性的图验证器负责最终判定"** —— 即"证据调查者与表达者"（呼应全文定位词升级）
