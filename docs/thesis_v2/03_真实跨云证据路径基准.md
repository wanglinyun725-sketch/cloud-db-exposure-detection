# 第三章 真实跨云证据路径基准

## 3.1 研究对象与设计原则

本章解决的不是“如何批量生成看起来像攻击的 JSON”，而是如何把分散的真实
公开材料转化为可追溯、可标注、可执行且不夸大独立性的路径级评测对象。本文将
原始事件限定为上游公开制品中已经存在的日志、配置、运行结果或事件记录。脚本
只承担下载、解压、字段规范化、去标识、索引和一致性校验，不得补写上游不存在
的攻击步骤；语言模型不得生成原始事件，也不得冒充人工标注者。

每个候选对象同时保存五类出处字段：

1. `source_id` 与上游发布者；
2. DOI、URL 或仓库 commit；
3. 许可证与可再分发范围；
4. 原始文件 SHA-256；
5. 归档内路径、事件索引或配置定位。

这个约束区分了“真实来源”和“真实生产流量”。受控靶场或研究数据集可以是真实
来源且可复现，但仍需明确标注为受控仿真，不能写成企业生产攻击。

## 3.2 数据对象与统计单位

原始材料被规范为四层对象：

- **source artifact**：上游原始归档或仓库快照；
- **case**：一个待标注的攻击、配置或负对照案例；
- **runtime instance**：可以由共同 Tool Use 契约查询的一段固定观测；
- **independence group**：共享攻击技术、模板、资源拓扑或近重复事件序列的
  最小谱系集合。

论文中的样本量、置信区间和显著性检验均以 independence group 为主要统计
单位。同一谱系的多个 payload 变体、不同时间戳 episode 或多个重复运行不能
扩大统计样本量。形式化地，令案例集合为 \(\mathcal C\)，分组映射为
\(\gamma:\mathcal C\rightarrow\mathcal G\)。任意训练—验证—测试划分
\(\mathcal S\) 必须满足：

\[
\forall g\in\mathcal G,\quad
\left|\{s\in\mathcal S:\exists c\in s,\gamma(c)=g\}\right|=1.
\]

即同一谱系只能出现在一个划分中。

## 3.3 候选库存与保守独立性审计

机器可读库存
`output/research_design/executable_lineage_inventory_v1.json` 记录 42 个
原始候选谱系：32 个具有真实运行观测，10 个具有固定配置事实。近重复审计发现
2 个运行时谱系存在相同序列指纹，在完成人工复核前两者均不计入最低数量门槛，
因此保守候选数为 40。

| 维度 | 当前可核验供给 | 证据含义 |
|---|---:|---|
| 原始候选谱系 | 42 | 去重前库存 |
| 近重复待复核 | 2 | 不计入最低门槛 |
| 保守独立谱系 | 40 | 数据治理数量门槛通过 |
| 上游来源 | 9 | awsgoat、azuregoat、cloudfoxable、cloudgoat、cross-cloud、gcpgoat、Splunk、Stratus、terragoat |
| 云平台 | 3 | AWS、Azure、GCP |
| 双人 gold 谱系 | 0 | 研究效果门槛未通过 |

因此，“40 个谱系、9 个来源、三云覆盖”只支持候选基准的广度主张，不支持
“40 个已准入金标准案例”或任何准确率结论。

## 3.4 确认性运行时盲标包

确认性数据包
`data/real_sources/annotation/runtime_confirmatory_30_unlabeled.json`
采用整谱系选择并排除两个碰撞组。当前固定供给为：

- 30 个 independence group；
- 52 个候选案例；
- 79 个 runtime instance；
- 2,548 条原始观测；
- 4 个运行证据来源；
- AWS 38、Azure 21、GCP 20 个运行实例。

四个运行证据来源分别为 CloudGoat、Cross-Cloud Observability、Splunk
Attack Data 和 Stratus Red Team。虽然完整候选库存有 9 个来源，确认性运行
实验的外推范围只能限定为这 4 个运行证据来源，不能把配置候选仓库也算作已经
验证的运行时泛化。

每个 runtime instance 对 Agent 隐藏 gold、攻击标签和 payload 条件，只暴露
工具查询后返回的观测。工具结果被截断时，只有实际渲染给策略的记录可被引用。
这保证了 Agent 无法通过读取数据包中的答案字段取得不当优势。

## 3.5 作用域感知的状态标注

路径边不是简单的二元标签。对关键命题 \(q\)，人工标注采用：

\[
y(q)\in\{
\text{Supported},
\text{Contradicted},
\text{Unknown},
\text{Conflict}
\}.
\]

其中 Supported 表示存在作用域充分的支持证据；Contradicted 表示存在作用域
充分的反证；Unknown 表示现有材料不能决定；Conflict 表示支持和反证并存。
Unknown 不能被自动转写为 Not-Reachable，受控实验中的 Root 操作也不能被
自动推断为具有外部低权限入口。

路径级标注还需要：

- canonical node sequence；
- canonical directed edge sequence；
- 每条边的证据 observation ID 与 raw ref；
- 作用域说明和不可判定原因；
- `Valid / Invalid / Insufficient / Conflict` 路径状态；
- 案例是否准入及排除原因。

节点和边类型必须使用
`configs/path_ontology_v1.json` 中冻结的 16 类节点和 27 类边。API 操作名是
证据值，不得直接伪装成语义边类型。

## 3.6 双人盲标、仲裁与一致性

两位不同真人先独立完成全部 30 个谱系，标注界面不显示任何方法输出。冻结程序
对任务包 SHA-256、标注者 ID、完整性和 schema 进行校验：

1. 两人一致的案例进入候选 gold；
2. 存在分歧的案例生成第三人仲裁任务；
3. 不删除争议难例；
4. 只有所有必填项完整、分歧解决且最低准入数满足时，才写出 reviewed gold
   和 group-safe split；
5. 输出采用 write-once，若同一路径已有不同内容则拒绝覆盖。

一致性至少报告原始一致率与 Cohen's kappa；多类别、缺失或不平衡条件下补充
Krippendorff's alpha。kappa 或 alpha 低于 0.70 时仍如实报告，并分析分歧
来自作用域、路径边界还是证据极性，不以删除难例提高数字。

当前 readiness 文件显示：

```text
stage = awaiting_double_blind
primary_complete_groups = 0
reviewer_complete_groups = 0
human_gold_independence_groups = 0
```

因此本节只定义协议，不能提前填写一致性结果。

## 3.7 外部负对照

错误 Reachable 是本研究的安全终点。外部负对照包包含 30 个候选事件，覆盖
AWS、Azure、GCP 和数据库、对象存储、备份、密钥、分析等数据面。它们必须由
两位真人判断是否确实不存在被所给证据支持的攻击/暴露路径；最低需要 20 个
可用负对照。负对照的“无攻击”不能由数据集名称或脚本规则代替人工判断。

零个错误 Reachable 也不解释为真实风险为零。若 \(n\) 个独立负对照中观测到
零事件，报告精确单侧上界：

\[
u_{1-\alpha}=1-\alpha^{1/n}.
\]

## 3.8 来源与谱系隔离冻结

人工 gold 完成后，冻结器同时绑定 source packet、reviewed gold、split、
负对照、ontology、外部 Sigma 先验、原始先验归档、Git commit 和模型锁。
冻结配置只有在 plan-only preflight 全部通过且研究代码与输入均已提交时生成。
任意输入发生一字节变化，后续预检均拒绝执行。

测试集只允许评估器读取。提示词、动作排序、停止规则、阈值和证书算法只能使用
development/validation 冻结前开发，不能根据 test 结果事后调整。

## 3.9 本章小结

本章的贡献是把真实公开云安全材料转化为一套可追溯、作用域感知并以谱系为独立
单位的路径基准协议。当前候选广度已经达到 40 个保守谱系、9 个来源和三云覆盖，
但 C1 的研究验收仍取决于 30 个谱系的双人盲标、仲裁和一致性报告。这个边界
使后续方法实验建立在真人 gold 上，而不是建立在生成脚本或模型自评上。
