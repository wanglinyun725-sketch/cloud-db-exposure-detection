# 题目

**面向云数据攻击与暴露路径的预算约束证据智能体方法研究**

## 中文摘要（冻结主实验前版本）

云数据库、对象存储、密钥服务与分析平台共同承载企业高敏数据。攻击者通常并非
利用单一高危配置直接取得数据，而是串联身份、网络、权限、资源策略和审计行为
形成多步路径。现有公开材料分散于攻击仿真日志、检测数据集、云靶场和基础设施
配置仓库，缺少来源可追溯、跨云且以路径为统计单位的统一评测；直接使用大语言
模型进行路径推断，又容易在证据不完整或作用域不明确时生成错误的
`Reachable` 结论。

本文围绕“真实证据基准”和“预算约束的主动路径发现”构建 Cloud DB PathBench。
第一，本文提出真实跨云证据路径基准协议：只解析公开上游制品，不由脚本或
语言模型生成所谓真实事件；保存来源、许可证、版本、文件哈希和原始证据定位，
并按攻击或配置谱系进行近重复审计和来源隔离。当前保守候选库存包含 40 个独立
谱系、9 个上游来源并覆盖 AWS、Azure 和 GCP；其中确认性盲标包包含 30 个完整
谱系、52 个候选案例、79 个运行实例和 2,548 条观测。该数字仅表示待标注供给，
最终准入数量与一致性必须由双人盲标、分歧仲裁和冻结程序确定。

第二，本文提出 EC-ReAct，将 ReAct 的“思考—行动—观察”循环约束为一个带
硬预算的序贯证据探查过程。智能体只能从当前可见证据构造工具参数；作用域守卫
区分云厂商原生的 `Reachable`、`NotReachable` 与无法判定；四值记忆保留
支持、反证、未知和冲突；成本—覆盖—分辨率—外部规则增益构成 Pareto 动作
前沿；引用守卫禁止提交未观察证据。语言模型负责提出下一工具调用和候选路径，
而结构、引用、字段断言与证据证书由确定性代码裁决。LangGraph 仅负责状态编排，
同一方法同时保留框架无关的线性运行器以验证语义一致性。

第三，本文实现 CP-Cert 冲突保持路径证书。该模块用支持位与反证位的四值格融合
证据，对成立路径求解最小成本正证书，对已枚举候选集求解反证 hitting-set，
并通过独立审计器检查充分性、原始引用完整性和删除不可约性。CP-Cert 当前已有
算法与工程测试，但只有当其在冻结人工金标准上降低 unsupported-path rate，
且路径级 F1 不发生超过预注册界限的退化时，才作为独立第三创新点；否则仅作为
EC-ReAct 的安全机制。

本文预注册在来源和谱系隔离的冻结协议下，分别使用本地
Qwen2.5-7B 和固定版本强模型，对比 vanilla ReAct、固定顺序、随机查询和
full-query，并执行六项单组件消融。唯一确认性主指标为预算 20 下的
Top-5 certified fine-grained exact edge F1，统计单位为独立谱系；同时报告
95% 置信区间、效应量、功效限制、Holm 校正、查询成本和错误 Reachable。
**最终数值结果与结论将在双人 gold、冻结划分和主实验完成后由机器决策文件
填入；在此之前不宣称方法有效。**

**关键词**：云数据安全；攻击路径；ReAct；工具调用；四值证据；可验证证书
